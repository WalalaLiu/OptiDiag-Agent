# Final Demo Guide

This guide describes how to run the final OptiDiag demo with the trained model and calibrated thresholds.

## 1. Prepare Runtime Files

Place the trained checkpoint on the server:

```text
models/checkpoints/best_model.pt
```

Place the calibrated threshold file generated by `scripts/evaluate.py`:

```text
runs/eval_thresholds.json
```

Both paths are intentionally ignored by Git. Do not commit `.pt`, `.pth`, `runs/`, `outputs/`, or generated datasets.

Runtime behavior:

- If `runs/eval_thresholds.json` exists and contains `per_class_thresholds`, `/analyze` uses per-issue thresholds.
- If no per-class thresholds exist but a global `best_micro_threshold` exists, `/analyze` uses that global issue threshold.
- If no threshold file exists, `/analyze` uses the default issue threshold `0.5`.
- If model or threshold loading fails, `/analyze` returns rule-based diagnostics instead of crashing.

## 2. Start the API

```bash
python scripts/run_api.py
```

Default service:

```text
http://127.0.0.1:8000
```

Health check:

```bash
curl http://127.0.0.1:8000/health
```

## 3. Upload an Image

File upload is preferred:

```bash
curl -X POST "http://127.0.0.1:8000/analyze" \
  -F "file=@outputs/demo_cases/images/01_over_exposure.png" \
  -F "experiment_type=diffraction"
```

URL input is also supported:

```bash
curl -X POST "http://127.0.0.1:8000/analyze" \
  -F "image_url=https://example.com/diffraction.png" \
  -F "experiment_type=diffraction"
```

If both `file` and `image_url` are provided, `file` takes priority.

## 4. Interpret Response Fields

Stable `/analyze` fields:

- `image_type`: predicted image type, or `unknown_or_estimated` without model output.
- `confidence`: image-type confidence from the model, or `0.0` without model output.
- `issues`: issue list after model thresholds or rule-based fallback.
- `metrics`: explainable image metrics used for rule-based interpretation.
- `diagnosis`: Chinese summary for the agent/user.
- `possible_causes`: likely experimental causes.
- `suggestions`: concrete operation guidance.
- `need_reacquire`: whether to reacquire after adjustment.
- `model_available`: whether the checkpoint was loaded successfully.
- `fallback`: which reasoning path was used.

Fallback values:

- `rule_based`: no usable model, or model disabled.
- `model_with_rule_based`: model output is used, while metrics and Chinese explanations are still rule-based.
- `rule_based_after_model_failure`: model was available but failed during prediction; rule-based diagnosis was returned.

## 5. Demo Cases

Generate report-ready cases:

```bash
python scripts/make_demo_cases.py
python scripts/visualize_demo_cases.py
```

Output:

```text
outputs/demo_cases/
  images/
  results/
  visualizations/
  summary.csv
```

Recommended screenshots:

- `outputs/demo_cases/summary.csv`
- one or two images from `outputs/demo_cases/images/`
- report visualizations from `outputs/demo_cases/visualizations/`
- `/analyze` JSON response in the terminal or API testing tool

## 6. Agent Plugin Setup

Export OpenAPI:

```bash
python scripts/export_openapi.py
```

Use either:

```text
http://SERVER_HOST:8000/openapi.json
```

or the exported:

```text
docs/openapi.json
```

In the agent prompt, ask the model to explain diagnosis through the returned metrics instead of only listing labels.
